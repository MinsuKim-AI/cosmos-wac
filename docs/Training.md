# 파인튜닝

공개 체크포인트(nvidia/Cosmos-Policy-LIBERO-Predict2-2B)를 교란 조건의 성공·실패 rollout으로 더 학습해, world model과 가치 예측이 실패 상황을 보게 한다. 이 모델로 H3(파인튜닝 후 탐지가 나아지는가)를 확인했다. 서버 명령과 감시 스크립트는 [서버 4090 파인튜닝](서버_4090_파인튜닝.md)에 있다.

## 데이터

| 구성 | 개수 |
|---|---|
| train 묶음 rollout | 100 에피소드 (성공 55, 실패 45, 16,054 step) |
| 공식 LIBERO-Spatial 시연 | 430 에피소드, 샘플 비율 25% |

calib과 eval 묶음은 학습에 넣지 않았다. 두 묶음은 탐지기의 보정과 평가에만 쓴다.

## 설정

| 항목 | 값 |
|---|---|
| 장비 | RTX 4090 0, 1번 (DDP) |
| 방식 | LoRA, rank 8, alpha 8 |
| 학습률 | 2e-5 |
| 배치 | GPU당 4 × 2장 × 누적 4 = 32 |
| 학습량 | 1 epoch, 샘플 210,432개, 갱신 6,576번 |
| 시간 | 11/20 08:27~17:36, 갱신당 4.95초 |
| 기록 | wandb `cosmos_policy_minsu_solo`, run `4090_lora_v2` |

GPU당 배치 4는 한 장에서 1, 2, 4, 8을 재서 골랐다. 4가 초당 1.89 샘플로 가장 빨랐고 8은 메모리가 부족했다.

## 공식 코드에서 고친 것

| 문제 | 원인 | 패치 |
|---|---|---|
| 두 GPU에서 첫 스텝 뒤 멈춤 | 로그 집계 `get_stat`이 샘플이 없는 rank에서 `all_reduce`를 건너뜀 | `wac/patches/cosmos_policy_ddp_get_stat.patch` |
| LoRA가 학습되지 않음 (v1) | meta 장치에서 만든 LoRA 층이 초기화되지 않아 A, B가 0으로 남음 | `wac/patches/cosmos_policy_lora_init.patch` |

## 합치기

마지막 체크포인트의 LoRA를 원래 가중치에 더해(W + (α/r)·B·A) 공개 체크포인트와 같은 형식으로 저장했다.

```bash
python wac/merge_lora.py <DCP model 폴더> <공개 .pt> ~/wac_cosmos/ft_ckpt/v2_iter6576.pt --alpha 8 --rank 8
```

LoRA를 단 280개 층이 모두 바뀌었다. 원래 가중치 대비 변화는 중앙값 1.8%, 최대 6.1%였고 NaN은 없었다.

## 결과

합친 모델로 calib과 eval을 기본 모델과 같은 초기 상태, 교란, seed로 다시 돌렸다(`wac/ft_collect.sh`, 400 에피소드).

| 조건 | 성공률 (기본→파인튜닝) | D AUROC (기본→파인튜닝) | 차이 [95%] |
|---|---:|---:|---:|
| 물체 이동 | 0.53→0.60 | 0.982→0.991 | +0.009 [−0.016, +0.036] |
| 손목 회전 | 0.45→0.39 | 0.779→0.887 | +0.108 [−0.010, +0.229] |

두 조건 모두 차이의 구간이 0을 포함해 H3는 지지되지 않았다. 자세한 비교와 중단 결과는 [실험 기록 7.3절](Experiment.md)에 있다.
