# 서버 RTX 4090 두 장에서 파인튜닝하기

서버 OASYS의 RTX 4090 0, 1번 두 장에서 GPU당 배치 4와 LoRA로 학습한다. LoRA는 원래 가중치를 고정한 채 작은 행렬을 학습한다. 두 장은 DDP로 묶어서 각 GPU가 모델 전체를 들고 서로 다른 샘플을 처리하고, 기울기만 합친다. NVIDIA가 공개한 LIBERO 전체 가중치 학습은 80GB GPU 여러 장을 썼다. [NVIDIA의 학습 환경과 LIBERO 설정](https://github.com/NVlabs/cosmos-policy/blob/main/LIBERO.md)

GPU 2, 3번은 데이터 수집에 쓴다.

## 준비된 것

| 항목 | 서버 위치 |
|---|---|
| Python 환경 | `~/wac_cosmos/cosmos-policy/.venv` |
| 학습기용 체크포인트 (공개 정책을 DCP 형식으로 변환) | `~/wac_cosmos/repo/data/finetune/base/libero_policy_dcp` |
| 공식 LIBERO-Spatial 시연 430개 | `~/wac_cosmos/repo/data/finetune/base/success_only` |
| 교란 rollout (train 묶음 100개, 16,054 step) | `~/wac_cosmos/repo/data/finetune/train_rollouts` |
| 데이터 구성 확인 결과 | `~/wac_cosmos/repo/data/finetune/wac_v1/dataset.json` |

`dataset.json`에 따르면 공식 로더가 한 epoch에 210,432개 샘플을 낸다(시연 52,608개, 성공·실패 rollout 각 78,912개).

## 배치 크기

GPU 한 장에서 배치마다 6스텝(누적 없이)을 돌려 쟀다. 스텝 시간은 모델 로드가 섞인 1번째와 VAE 인코더를 컴파일하는 5번째를 빼고 2~4번째 스텝의 평균이다.

| GPU당 배치 | 스텝당 시간 | 초당 샘플 | GPU 메모리 |
|---|---|---|---|
| 1 | 1.58초 | 0.63 | 8.5GB |
| 2 | 1.70초 | 1.18 | 11.7GB |
| 4 | 2.12초 | 1.89 | 17.5GB |
| 8 | | | 메모리 부족 |

배치를 키워도 스텝 시간은 조금만 늘어서 배치 4가 가장 빠르다. 배치 8은 24GB에 들어가지 않는다. 유효 배치 32를 누적으로 정확히 맞추려면 32의 약수여야 해서 5~7은 쓰지 않는다. 그래서 GPU당 배치 4로 정했다. 각 배치는 6스텝씩만 재서, 오래 돌렸을 때의 평균과는 조금 다를 수 있다.

두 장(DDP)에서 배치 4로 8스텝을 돌린 결과, 스텝당 1.6~1.7초(8샘플, 초당 약 4.8샘플), GPU당 최대 메모리 14.5GB였다. 한 epoch(210,432샘플)는 이 속도로 약 12시간이다. 한 장(배치 4)이면 약 31시간이다.

## 공식 코드 수정

공식 코드의 로그 집계 함수 `get_stat`은 해당 구간에 샘플이 없는 GPU에서는 `all_reduce`를 건너뛴다. 배치가 작으면 한쪽 GPU에만 어떤 종류의 샘플이 들어오는 일이 잦아서, 두 GPU가 서로 다른 통신을 기다리며 첫 스텝 뒤에 멈췄다. `TORCH_DISTRIBUTED_DEBUG=DETAIL`로 돌려서 두 rank가 같은 순번에 서로 다른 `all_reduce`를 부르는 것을 확인했다.

서버의 공식 코드 사본에서 아래 두 함수를 고쳐, 모든 GPU가 항상 (합계, 개수)를 `all_reduce`하고 전체 평균을 내게 했다. 학습 계산은 그대로이고 로그에 찍히는 loss 평균만 바뀐다. 고친 곳에는 `cosmos-wac 수정` 주석이 있다.

- `cosmos_policy/config/callbacks.py`의 `_LossRecordNoEDM.get_stat`
- `cosmos_policy/_src/predict2/callbacks/wandb_log.py`의 `_LossRecord.get_stat`

수정 내용은 `wac/patches/cosmos_policy_ddp_get_stat.patch`에 있다(공식 코드 커밋 `18a2acc` 기준). 새로 받은 공식 코드에는 `git -C <cosmos-policy 경로> apply <이 저장소>/wac/patches/cosmos_policy_ddp_get_stat.patch`로 적용한다.

RTX 4090은 GPU 사이 P2P를 지원하지 않아서 `wac/run_lora.sh`에 `NCCL_P2P_DISABLE=1`도 넣었다.

## 몇 스텝 확인

서버에 접속해서(`ssh OASYS`) 0, 1번이 비어 있는지 본 뒤 8스텝만 돌린다. 공개 체크포인트에서 시작하고, LoRA의 rank와 alpha는 8, 학습률은 `2e-5`다. 시연 샘플은 25%, 교란 rollout 샘플은 75%로 둔다. 설정은 `wac/run_lora.sh`에 있다.

```bash
cd ~/wac_cosmos/repo
nvidia-smi --query-gpu=index,memory.used --format=csv
bash wac/run_lora.sh 4090_lora_check 8 1 1000
```

끝나면 `data/finetune/4090_lora_check/train.log`에 `Iteration 5`까지 찍히고 마지막에 `Done with training`이 나오는지 본다. loss가 유한한지도 확인한다.

## 본 학습

GPU 두 장이 한 번에 4개씩, 합쳐서 8개를 넣고 4번 누적해서 유효 배치를 32로 맞춘다(4 × 2 × 4). 한 epoch에 210,432개 샘플이므로 가중치를 6,576회 갱신하고, 약 12시간 걸린다. `nohup setsid`로 띄우면 SSH 접속이 끊기거나 노트북을 꺼도 서버에서 계속 돈다.

```bash
cd ~/wac_cosmos/repo
nohup setsid bash wac/run_lora.sh 4090_lora_v1 epoch > ~/wac_cosmos/lora_v1.out 2>&1 < /dev/null &
tail -f data/finetune/4090_lora_v1/train.log
```

`tail -f`는 `Ctrl+C`로 끄면 되고, 학습은 그대로 돈다.

학습이 도중에 죽으면 다시 띄우도록 감시 스크립트를 함께 띄운다. 프로세스가 없는데 로그에 `Done with training`이 없으면 GPU 0, 1번이 빌 때까지 기다렸다가 같은 명령으로 다시 시작하고, 학습 코드가 `latest_checkpoint.txt`의 마지막 체크포인트부터 이어 간다. 최대 5번까지 다시 띄운다.

```bash
nohup setsid bash wac/watch_lora.sh 4090_lora_v1 > ~/wac_cosmos/watch_lora.log 2>&1 < /dev/null &
cat ~/wac_cosmos/watch_lora.log     # 다시 띄운 기록
```

로그와 체크포인트는 `~/wac_cosmos/repo/data/finetune/4090_lora_v1/`에 남는다. 학습 기록은 wandb 프로젝트 `cosmos_policy_minsu_solo`에서도 볼 수 있다. 비교 실험에서는 LoRA 설정을 같이 기록하고, 학습에 쓴 `train`과 별도로 `calib`과 `eval`을 사용한다. [실험 기록](Experiment.md)
